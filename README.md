# Учебная платформа BURAQ (BURAQ o‘quv platformasi)

Обучение сотрудников: курс по стандартам компании, тесты и устный экзамен у SOP-менеджера, план адаптации 30/60 дней,
уровни, рейтинг, журналы и термины, кейсы, ошибки и наставники, сверхзадачи, опросы, учёт турникета и отметка прихода в программе.
Роли: **CEO** (всё), **SOP-менеджер** (обучение и сотрудники), **руководитель компании** (владелец: смотрит всё,
отвечает на свои идеи), **Project Manager** (только свои идеи) и **сотрудник**; наставник — сотрудник с отметкой
«наставник». Кто что видит и меняет — «Роли и доступ».

Сайт: **https://buraqlearning-production.up.railway.app/** — Railway: страница, сервер и данные по одному адресу
(см. «Railway»). GitHub Pages (`https://buraqlogisticsuz.github.io/Buraqlearning/`) перекидывает туда —
адрес в `SITE_URL` в `.github/workflows/pages.yml`.
Репозиторий: [buraqlogisticsuz/Buraqlearning](https://github.com/buraqlogisticsuz/Buraqlearning).
Старый адрес `…/xeeds/learn/` перекидывает на GitHub Pages, а оттуда — на Railway.

## Как вносить изменения

Код сайта живёт на GitHub — менять его можно с любого компьютера, правка сохраняется в репозитории и через 1–2 минуты
появляется на сайте (Railway и GitHub Pages пересобираются сами после каждого пуша в `main`):

- **В браузере:** github.com → файл → ✎ → **Commit changes** (в основную ветку).
- **С Claude:** [claude.ai/code](https://claude.ai/code) → репозиторий `buraqlogisticsuz/Buraqlearning` → опишите
  правку словами.
- **На своём компьютере:** `git clone https://github.com/buraqlogisticsuz/Buraqlearning` → правка → `git push`.

Данные платформы (сотрудники, прогресс, тексты уроков) — не в репозитории, а на сервере: их меняют на самом сайте,
и они общие для всех устройств. Обновление кода данные не трогает.

## Публикация (GitHub Pages)

1. Один раз: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. Каждый пуш в основную ветку: `.github/workflows/pages.yml` прогоняет тесты (`node --test tests/*.test.mjs`) и
   выкладывает страницу-перенаправление на Railway (`SITE_URL`; пусто — сам сайт). Запустить вручную:
   **Actions → Deploy to GitHub Pages → Run workflow**.

## Только с сервером

Платформа работает только с сервером: вход по логину и паролю от SOP-менеджера, общие данные для всех устройств.
Внизу страницы — «Ma’lumotlar BURAQ serverida saqlanadi». Демо (выдуманные сотрудники, данные в браузере) убрано
13.10.2026; страница без адреса сервера пишет «Server ulanmagan». Ссылка `?demo=1` ведёт на обычный вход.

**Тексты стандартов (2-bob, 4-bob и следующие главы) в репозиторий не попадают:** репозиторий открытый. CEO или
SOP-менеджер загружает тексты и тесты на сервер из файла («Kontent» → «⇪ Fayldan yuklash»), сотрудники получают
их только после входа.

**«Kontent» → «Darslar»** — слева карточки глав (**bob**): номер, название, «N ta dars · M ta savol», строка
«Kimlar o‘qiydi: …». Карточка раскрывается: уроки (**dars**; без теста — пометка «test yo‘q»), «+ Dars qo‘shish»,
название главы, «faqat rasmiy xodimlar». Над карточками — «⇪ Fayldan yuklash» и «+ Yangi bob». Внизу каждой карточки —
корзина «Bobni o‘chirish» (и ссылка в раскрытой главе): окно `SecDelModal` говорит, сколько уроков уйдёт, сколько открытых
вопросов и заявок на экзамен закроется и сколько сотрудников их проходили (XP остаётся, в освоение и рейтинг уроки больше
не идут); главу с уроками — только после галочки «Ha, bobni darslari bilan o‘chiraman», пустую — сразу. Программы главу забывают. Пока урок не выбран, справа — подсказка
в три шага.

**Редактор урока.** Внизу — панель, которая всегда на экране: «● Saqlanmagan o‘zgarishlar» / «✓ Saqlangan»,
«Xodim ko‘rinishi» (урок так, как его увидит сотрудник: название, введение, текст, шаги, граница ответственности,
видео справа, сколько вопросов в тесте — из несохранённого черновика) и «Saqlash» (или **Ctrl+S / ⌘S**). Другой урок
при несохранённых правках — окно «Saqlanmagan o‘zgarishlar»: «Saqlash va o‘tish» (если урок уже сдавали — остаёмся,
чтобы сообщить им об изменении), «Saqlamasdan o‘tish», «Bekor qilish»; закрыть вкладку — браузер переспросит.
**Текста стандарта в редакторе урока нет** — он приходит только из Word («Word fayldan yuklash», у главы — «Bobni
almashtirish»); в «Kontent» правятся название, введение, шаги, граница ответственности, видео и тест. Увидеть текст —
«Xodim ko‘rinishi»; AI («Matnni tuzilmaga keltirish», своё задание) показывает новый текст до «Qo‘llash». Окна страницы
(`Modal`) рисуются поверх всего (portal в `<body>`), а не внутри липкой колонки глав.

**AI в «Kontent»** (ключ Claude — только на сервере, в модель уходит лишь текст урока, без данных сотрудников):
в уроке — «Test savollari tuzish», **«Standartni tekshirish»** (что неясно новому сотруднику: кто / когда / сколько не
сказано, противоречия, пропущенные шаги, опечатки — до 8 находок «Joy · Muammo · Taklif», только советы, текст не
меняется; где данных нет — «[SOP menejeri aniqlaydi]»), «Matnni tuzilmaga keltirish», «Qisqa kirish yozish»,
«Qadamlarni ajratish», своё задание. У главы — **«✦ AI bilan to‘ldirish»** (`ChapterAI`): для уроков с текстом, где
нет теста, введения или шагов (галочки, сколько таких уроков, число вопросов 3–10), AI готовит черновики урок за
уроком (полоса «3 / 18 · название», «To‘xtatish»); результат — список с галочками и «Ko‘rish» (вопросы с отмеченным
верным ответом, введение, шаги), «Qo‘llash — N ta dars» записывает только отмеченное. То, что в уроке уже есть, не
заменяется; если открытый урок с несохранёнными правками в списке — сначала сохранить.

**Место урока в главе** — строка над редактором урока «Bobdagi o‘rni: 5 / 18»: «↑ Yuqoriga», «↓ Pastga»,
«Oldingi darsga qo‘shish» (с подтверждением: текст, шаги, вопросы теста и связанные кейсы уходят в конец предыдущего
урока, название — подзаголовком; если урок уже начали сотрудники — сколько их, их статус по нему не сохранится) и
«Darsni bo‘lish» (с какого подзаголовка H начать новый урок — он встаёт сразу за текущим, вопросы теста остаются).
После каждого действия уроки главы с номером перенумеровываются, подзаголовки — за номером урока. Пока урок не
сохранён, менять его место нельзя («Avval darsni saqlang»). У главы — **«Raqamlarni tartiblash»**: убирает двойные
номера из названий («3.2. 2. ajratiladigan…» → «3.2. Ajratiladigan…»), отделяет приклеенный подзаголовок
(«…TARTIBI4.1. Uchrashuvdan oldin» → заголовок урока и подзаголовок «3.3.1. Uchrashuvdan oldin» в начале текста) и
нумерует уроки по порядку; «Kirish» не нумеруется.

**Что можно загрузить** («⇪ Fayldan yuklash»):
- **Word (.docx)** — глава как есть, разбирается в браузере: заголовки, жирный/курсив, списки, таблицы, картинки
  (сервер сохраняет их файлами), «ILOVA» — отдельной рамкой. Уроки начинаются после строки «N-BOB. …» (всё, что выше, —
  титул и гриф, не загружается). В окне: по каким заголовкам резать на уроки (уровень заголовка или «весь файл —
  один урок»), брать ли вступление до первого заголовка уроком «Kirish», и **список всех заголовков** с отступом по
  уровню: отмеченный начинает урок (виден его итоговый номер и название, сколько в нём слов), снятый остаётся внутри
  урока подзаголовком (`→ 3.4 darsi ichida`; до первого урока без «Kirish» — `yuklanmaydi`). Любой заголовок
  отмечается или снимается вручную — в списке выбора тогда «Qo‘lda tanlangan — N ta dars». Тестов в Word нет — их
  добавляют в редакторе урока или файлом .json.
  **Номера.** Уроки нумеруются по порядку «3.1, 3.2…», собственный номер заголовка из файла убирается («2. AJRATILADIGAN
  HARAJAT TURLARI» → «3.2. Ajratiladigan harajat turlari», заголовок капсом — обычным регистром), а подзаголовки урока
  идут за его новым номером («2.1. Yo‘l puli» → «3.2.1. Yo‘l puli»; в абзацах — только «2.1.» с точкой, «2.5 kg» не
  трогается). Заголовок с переносом строки («4. … ⏎ 4.1. …») — заголовок и подзаголовок, не одна склеенная строка.
  Жирный или капсом абзац с номером, который закрывает пропуск в номерах заголовков («3. LIMITLAR» между заголовками
  «2.» и «4.»), считается заголовком того же уровня. Заголовок без текста под ним («…STANDARTI» перед «1. MAQSAD») —
  название того, что идёт следом: следующий заголовок остаётся в его уроке.
- **Файл главы (.json)** — глава с тестами, подготовленная вне репозитория:
```
{ "app": "buraq-lms-chapter", "v": 1, "tracks": ["tr_mgr"] | "all",
  "aud": { "positions": ["…"], "depts": ["…"], "users": ["…"] } | { "all": true },   ← необязательно
  "section": { "id": "b2", "title": "2-bob. …", "officialOnly": false,
    "lessons": [{ "id": "b2-1", "title": "2.1. …", "html": "<h3>…</h3><p>…</p>", "quiz": [{ "q": "…", "options": ["…", "…"], "answer": 0 }] }] } }
```
- `.html` прототипа из Claude (4-bob) — как раньше.

Окно загрузки («Bobni yuklash»): **«Qayerga»** — новая глава (встаёт перед первой главой с бо́льшим номером по «N-bob»
в названии), заменить выбранную главу (её название и уроки — из файла) или добавить уроки в выбранную главу;
**«Kimlar o‘qiydi»** — см. ниже (по умолчанию — как у заменяемой главы, из `aud` файла или из `tracks`: «all» — все,
программы — их должности). HTML проходит тот же фильтр, что и редактор курса; неверные вопросы отбрасываются; номера
уроков, занятые в другой главе, — отказ без изменений.

**Кто проходит главу** — строка «Kimlar o‘qiydi: …» на карточке (то же окно выбора), `section.aud`:
- «Hamma xodimlar» — `{ all: true }`;
- иначе любое сочетание: должности (`positions`), отделы (`depts`), сотрудники поимённо (`users`, id) — главу
  получает тот, кто подходит хотя бы под одно. Рядом с должностью и отделом — сколько в них сейчас людей, внизу —
  сколько получат главу.
Сервер (v12) остальным главу не отдаёт, а в списке поимённо назначенных каждый видит только себя. Глава без `aud`
(загруженная раньше) идёт по программам (`tracks[].sections`), как до v12; `section.users` (v11) читается как
поимённый список. Уроки открываются по порядку, поэтому главу лучше давать только тем, кому она нужна.

ИИ-помощники (наставник, кейсы, опросы, редактор курса) работают через сервер — см. «ИИ» ниже.

## Railway (основной сервер)

Сайт и сервер — один сервис Railway из этого репозитория: `npm start` → `server/index.mjs`. Он отдаёт страницу,
отвечает на запросы `/api` тем же кодом сервера, что и Apps Script (`tools/lms-gs/Server.gs`), и хранит данные
на томе (Volume) Railway. Обновление: пуш в `main` → Railway пересобирает сайт сам, данные на томе остаются.

### Запуск (один раз, ~10 минут)

1. [railway.com](https://railway.com) → **New Project → Deploy from GitHub repo** → `buraqlogisticsuz/Buraqlearning`.
   Если репозитория нет в списке — **Configure GitHub App** → дать доступ организации `buraqlogisticsuz`.
2. **Том для данных:** на схеме проекта правой кнопкой по сервису → **Attach Volume** → Mount path: **`/data`**.
   Без тома платформа не запускается: на сайте — «Server sozlanmagan» с этой подсказкой, в журнале — «Нет тома для данных»
   (иначе данные пропадали бы при каждом обновлении). После подключения тома нажмите **Deploy**.
3. Сервис → **Settings → Networking → Generate Domain** — адрес сайта вида `…up.railway.app` (можно подключить свой домен).
   Там же, в **Settings**, регион поближе к Ташкенту — Европа (EU West).
4. **Deployments → View logs** — при первом запуске там **логин и пароль SOP-менеджера**. Запишите: больше нигде не показываются.
5. Проверка: `https://<адрес>/api` отвечает `{"ok":true,"app":"buraq-lms","v":7,"ready":true}`.
6. Дальше — как в «Настройке Apps Script» с шага 8: первый вход SOP-менеджера, загрузка 4-bob, сотрудники.

### Уведомления в Telegram

Бот присылает человеку его уведомления с платформы (ответ на вопрос, итог экзамена, ответ на идею, новая задача…)
и вечером — напоминание учиться, если за день меньше 2 часов (в «время напоминания» сотрудника, по Ташкенту).

1. В Telegram — [@BotFather](https://t.me/BotFather) → `/newbot` → имя (например, «BURAQ o‘quv») и адрес бота
   (например, `buraq_oquv_bot`) → BotFather пришлёт **токен** вида `123456789:AA…`.
2. Railway → сервис → **Variables** → `TELEGRAM_BOT_TOKEN` = токен. После перезапуска в журнале: «Telegram: бот @… подключён».
3. Каждый подключает себя сам: «Mening profilim» → «Telegram’ni ulash» → в боте **Start**. Отключить — там же или `/stop`.

Токен не показывайте никому: с ним можно писать от имени бота. Работает только на сервере Railway (не в Apps Script).

### Копия данных у себя

CEO, SOP-менеджер или руководитель: меню под именем → **«Ma’lumotlarni yuklab olish»** — один JSON-файл со всеми
данными и файлами (сканы, вложения), которые видны этому входу: идеи, адресованные другим, — без текста,
у SOP-менеджера — без зарплаты. Полная копия — у CEO.
Храните файл в надёжном месте (например, раз в неделю — на Google Диск компании); это вторая копия вдобавок к Railway.

### Свой домен (buraqbilim.com)

1. Домен должен быть куплен (любой регистратор .com; удобно — Cloudflare: там же бесплатный DNS).
2. Railway → сервис → **Settings → Networking → Custom Domain** → `buraqbilim.com` (по желанию ещё `www.buraqbilim.com`).
   Railway покажет DNS-записи (CNAME на адрес `…up.railway.app`, иногда ещё TXT для проверки).
3. У регистратора → DNS → добавить эти записи как есть. Для домена без www нужен DNS, который умеет CNAME на корне
   (CNAME flattening, ALIAS или ANAME) — например, Cloudflare; там у записей — «DNS only» (серое облако).
4. Когда Railway покажет зелёную галочку (обычно минуты, иногда несколько часов), HTTPS он настраивает сам.
5. Сервис → **Variables** → `SITE_HOST` = `buraqbilim.com`: старый адрес `…up.railway.app` перекидывает страницы на новый
   (запросы `/api` — нет, чтобы открытые вкладки не теряли правки). Вход на новом адресе — заново: он хранится в браузере
   для каждого адреса отдельно.
6. GitHub Pages: `SITE_URL` в `.github/workflows/pages.yml` — новый адрес.

**Переменные** (сервис → **Variables**): `ANTHROPIC_API_KEY` и `AI_*` — ИИ (см. «ИИ»); `NEW_ADMIN` — забыли пароль
SOP-менеджера: задайте любое новое значение (`1`, потом `2`…) → после перезапуска в журнале новый вход (`metodist2`, …).
`SITE_HOST` — свой домен (см. выше). `DATA_DIR` — другая папка для данных (обычно не нужна: путь тома Railway сервер берёт сам).

**Данные на томе:** `props.json` (учётные записи — только хэши паролей, входы), `drive.json` (список файлов) и папка
«BURAQ o‘quv platformasi — ma’lumotlar»: `state.json`, `files/` (сканы, вложения), `backups/` (копия каждую ночь
в 03:00 по Ташкенту, 30 дней). Копии лежат на том же томе — включите ещё резервные копии самого тома:
том → **Backups** (расписание).

Платный тариф Railway: сервис работает постоянно; плата — за время работы и объём тома.

## Сервер на Google Apps Script (запасной вариант)

Тот же код сервера можно запустить бесплатно в Google Apps Script — тогда страница остаётся на GitHub Pages, а адрес
`…/exec` вписывается в `config.js`. Отдельный проект Apps Script — **не** скрипт таблицы отгрузок.

- **Данные** — файл `state.json` в папке «BURAQ o‘quv platformasi — ma’lumotlar» на Google Диске владельца
  скрипта. Каждую ночь в 03:00 (Ташкент) — копия в `backups/state-ГГГГ-ММ-ДД.json`, копии хранятся 30 дней.
- **Файлы** — сканы паспортов из анкеты, вложения журналов и сверхзадач — в папке `files` рядом с `state.json`, в данных
  остаётся ссылка `lmsfile:<id>`. Файл сервер отдаёт только тому, кому видна эта ссылка: свой паспорт — сотруднику,
  все — SOP-менеджеру. (Без этого `state.json` вырос бы за пределы 10 МБ, которые Apps Script может записать.)
- **Вход** — логин и пароль проверяет сервер. Пароли хранятся только как PBKDF2-SHA256 с солью (10 000 повторов)
  в свойствах скрипта, в `state.json` их нет. После 5 неверных паролей подряд логин закрыт на 15 минут. Вход на
  устройстве живёт 30 дней с последнего запроса, у одного человека — до 10 устройств.
- **Страница входа:** интро ~5 секунд (лесенка, стрелка; фура с контейнером в атласе — узор маргиланской ткани
  в фирменных цветах, логотип на тёмно-синей табличке — едет из Yiwu, Zhongshan, Istanbul или Moskva в Toshkent,
  каждый раз из другого города), приветствие по времени суток на устройстве и **«Kun hikmati»** — одна мудрость в день,
  стрелка — следующая. Стандартные — 12 узбекских пословиц и слоган BURAQ (`strings.js`, `wz_1`…; по-русски,
  по-английски и по-китайски под оригиналом — смысл). Свои SOP-менеджер добавляет в «Kontent» → «Kun hikmati»
  (`settings.wisdom`), там же выключает стандартные. Страницу видят до входа, поэтому сервер отдаёт ей только этот
  список (действие `wisdom`). Форма входа и «Kun hikmati» — одна и та же стеклянная карточка
  (полупрозрачная, светлая кромка 1 px, мягкая тень; `lor.css`, «one glass card»), правая часть — спокойная. На телефоне фуры и цитаты нет — сразу
  форма входа.
- **Дневная и ночная тема** («Ko‘rinish»: Kunduzgi · Avto · Tungi; `lor.css`, блок «DAY PASS» в конце). Днём страница
  сама говорит браузеру «светлая» (`color-scheme: light`): на телефоне или ноутбуке в тёмном режиме с выбранным
  «Kunduzgi» поля, календарь, полосы прокрутки и автозаполнение Chrome больше не тёмно-серые. Автозаполненные
  «Login» / «Parol» — белое поле с синим текстом (тень-заливка `--field-solid` поверх цвета браузера). Днём карточки —
  белые листы с тонкой синей кромкой, шапка — синий бренда, поля белые с заметной рамкой, отметки ответов и
  переключатели — с рамкой поля. Ночь не меняется: её селекторы весомее голого `:root`, а у новых переменных
  (`--field`, `--field-solid`, `--gc-ring`, `--ctl-edge`, `--sw-off`, `--sw-knob`) ночное значение — прежнее.
  Проверка — `tests/lms-theme.test.mjs` (у каждой дневной переменной есть ночная, цвета — только оттенки пяти
  фирменных) и шаг «день на тёмном телефоне» в `tests/lms-e2e.mjs`. На телефоне список уведомлений — во всю ширину
  шапки (раньше уезжал за левый край).
- **Приветствие и обязательное знакомство** («Kontent» → **«Tanishuv»**, `settings.welcome`). Меняют **SOP-менеджер и CEO**,
  руководитель только смотрит. Два блока:
  - **«Salomlashuv»** — заголовок и текст первого шага, который видит новый сотрудник при первом входе (пусто — стандартный
    текст `w1_t`/`w1_p`).
  - **«Majburiy tanishuv»** — текст, **документы** и видео о компании (ссылка YouTube или прямой `.mp4`; другая ссылка —
    кнопкой «открыть»). Документы — **PDF и Word**: перетащить файл в рамку или выбрать на компьютере, до 5 файлов, каждый
    до 20 МБ (за одно сохранение — до 25 МБ новых файлов: запрос с файлами в base64 не больше `MAX_BODY`). В списке —
    состояние («Saqlanmagan» → «Yuklanmoqda…» → «Saqlangan»), просмотр, порядок ↑ ↓, удаление. При «Saqlash» сервер
    кладёт файл на Диск (`storeFiles_`), в `settings.welcome.docs[]` остаётся `{ id, name, size, type, data: 'lmsfile:…' }`;
    отдаёт его `file_` — тому, кому ссылка видна (знакомство видят все). У документа — **название для сотрудников**
    (`title`, правится в списке; по умолчанию — имя файла без «_» и номера версии: «Korxona_haqida_v5.pdf» → «Korxona
    haqida»). Сотрудник читает **прямо на сайте и только смотрит**: PDF — **страницами-картинками** (`PdfPages`, pdf.js 3.11
    из `js/vendor/`, грузится при первом PDF; просмотра браузера нет — в нём всегда «сохранить» и «печать»; то же на телефоне),
    **«Yuklab olish» и «Yangi oynada ochish» у сотрудника нет** — скачать файл могут только SOP-менеджер и CEO в редакторе
    (у них PDF — встроенный просмотр браузера, на телефоне — карточка «Hujjatni ochish»), `.docx` — текстом из файла (тот же разбор, что
    у импорта главы: заголовки, списки, таблицы, картинки), старый `.doc` — только скачать (редактор подсказывает сохранить
    его в Word как PDF/DOCX). **Знакомство обязательно для всех сотрудников** (`introMust`): отложить, закрыть крестиком или Escape нельзя — только подтвердить или выйти из аккаунта; новый сотрудник проходит его последним шагом входа («Oxirgi qadam»), работающий — при входе, а если SOP-менеджер добавил или изменил знакомство, пока он на сайте, окно открывается само («Majburiy tanishuv»). **С документами знакомство — на весь экран** (`IntroReader`): слева документ во всю высоту
    (PDF — страницами, Word — текст; несколько документов — вкладки в шапке), справа **видео этого документа**
    (`docs[].video.src` — своё поле у каждого документа в редакторе; нет своего — общее видео знакомства; нет никакого —
    окно видео всё равно справа, с заставкой «Video tez orada qo‘shiladi», а в предпросмотре SOP / CEO — где вставить ссылку), текст,
    в шапке — кнопки **«Hujjat» / «Video»**: скрыть окно (только документ на весь экран или только видео крупно; оба скрыть
    нельзя, выбор помнит браузер); галочка и кнопки — внизу на всю ширину. Так же — у нового сотрудника и в окне у
    работающих; в редакторе — «Xodim ko‘rinishida to‘liq ekranda ochish». На телефоне — документ сверху, видео и кнопки ниже.
    **Порядок входа нового сотрудника:** анкета и тест («Savolnoma»; с «Birinchi navbatda» — ещё до приветствия, без неё —
    окном после профиля) → приветствие и условия → профиль → **знакомство в самом конце** («Oxirgi qadam», `introMust`:
    сотрудник принял условия уже при этой версии знакомства). Отложить его нельзя — ни «Keyinroq», ни крестика, ни Escape
    (только выйти из аккаунта), пока **не откроет все документы** и не отметит «Tanishuv materiallari bilan to‘liq
    tanishdim»; потом — окно отметки прихода. Работающим сотрудникам (знакомство добавили или изменили позже) при входе
    открывается окно, которое можно отложить (до окна отметки прихода), на главной висит синяя плашка,
    пока не подтвердят; пересмотреть можно из меню пользователя («Kompaniya bilan tanishuv»). Подтверждение —
    `users[].introSeenAt` (+ запись `intro-seen` в журнале). Изменили **текст, видео, состав документов или видео документа** (порядок и названия не в счёт) знакомства — новая версия (`at`),
    и все подтверждают заново; правка только приветствия повторного подтверждения не требует. Справа в редакторе — как это
    увидит сотрудник и **кто подтвердил** («n / m», список ещё не подтвердивших).
- **Обязательная анкета сотрудника** («Kontent» → **«Savolnoma»**, `settings.questionnaire`) — чтобы компания лучше узнала
  человека; правильных ответов нет. Вопросы пишут **SOP-менеджер и CEO** (руководитель только смотрит): вручную, **списком
  из текста** или **из Word (.docx)** — строка или пункт нумерованного списка → вопрос, «- …» / «a) …» / маркированный список
  → варианты к вопросу выше, «# …» / заголовок Word → подзаголовок раздела. Типы ответа: развёрнутый, короткий, один
  вариант, несколько вариантов, оценка 1–5; у каждого — «Majburiy». Галочка «Savolnoma yoqilgan» включает и выключает её.
  Сотрудник: при входе окно (после знакомства, до отметки прихода), на главной синяя плашка, в меню пользователя —
  «Xodim savolnomasi», чтобы посмотреть и поправить. Без ответов на обязательные вопросы не отправить; «Keyinroq» сохраняет
  черновик. Ответы — в своей карточке, `users[].qa = { answers: { <id вопроса>: … }, at, consent, meta, prev, retake, dirty }` (+ `qn-done` в журнале;
  `meta`, `prev`, `retake` — см. «Качество ответов»; `dirty` — черновик поверх уже отправленной анкеты: она «к заполнению»,
  пока не нажмут «Yuborish», — черновик сам не снимает «Birinchi navbatda» и не обходит проверки отправки); сервер
  отдаёт чужие карточки сотрудникам только публичными полями (`PUBLIC_USER`), так что ответы видят **сам сотрудник, CEO,
  SOP-менеджер и руководитель**, коллеги — нет. Добавили новый обязательный вопрос — сотрудник снова видит анкету с прежними
  ответами и отвечает только на новое. Справа в редакторе: кто отправил («n / m»), ответы человека (по клику на имя), кто
  ещё не отправил (с черновиком — тоже по клику) и **«Javoblarni yuklab olish»** — CSV для Excel: строка на сотрудника,
  столбец на вопрос (плюс темперамент, баллы и выводы шкал).
  - **Как анкета кандидата** (например, «Nomzod anketasi»). Типы ответа ещё: **дата**, **таблица** (строки × столбцы —
    языки и уровни), **согласие** (галочка; дата отправки и логин — как подпись). У вопроса: **«Asosiy»** — столбец в
    таблице результатов и плашка в карточке; **«Maxfiy»** — паспорт, родители, здоровье: точками, пока CEO / SOP-менеджер
    не нажмёт «показать», и **не уходит в ИИ**; **«Profilga»** (`prof`: name, birth, phone, telegram, email, address,
    passport, emg) — ответ подставится в профиль, второй раз не вводить. Загрузка текстом или файлом **.txt / .docx** с
    пометками в конце строки: `[qisqa] [batafsil] [sana] [tanlov] [bir nechta] [baho] [jadval: A | B | C] [rozilik]
    [ixtiyoriy] [asosiy] [maxfiy] [profil:email] [agar: Oilali]`, строки `@sarlavha: …`, `@kirish: …`, `@birinchi`. Сам
    текст анкеты компании в репозиторий не кладём — файл загружают в «Kontent» → «Savolnoma».
  - **Раздел только для кандидатов или только для штатных** (`section.aud`, `qnForU`): у раздела в редакторе —
    «Kimga ko‘rsatiladi: Hammaga / Faqat nomzodlarga (sinov muddati) / Faqat rasmiy xodimlarga»; в тексте — пометка у
    заголовка `# Nomzodlik haqida [faqat nomzod]` или `[faqat rasmiy]`. Остальным раздел со всеми вопросами не
    показывается и не обязателен; кандидат — статус «Sinov muddati», штатный — «Rasmiy xodim» (страница «Xodimlar»).
  - **Вопрос по условию** (`when: { q, any }`): виден, только если в вопросе с вариантами выше выбран один из
    отмеченных вариантов — «Farzandlaringiz soni» только при «Oilali». В редакторе — строка «Har doim ko‘rsatish /
    Faqat agar «…» savolida tanlansa:» и варианты-чипы; в тексте — `[agar: Oilali]` (или `[agar: A | B]`: ближайший
    выше вопрос с таким вариантом). Скрытый вопрос не обязателен, не нумеруется, его ответ не сохраняется (`qnShowIf`).
    **Подсказка:** вопрос про детей или супруга недалеко (до 10 пунктов) после вопроса с одним выбором, где есть
    «Oilali / Uylangan / Turmush qurgan / Женат…», и без условия — кнопка «Shart qo‘shish: faqat «Oilali» bo‘lsa» ставит
    условие одним щелчком (шаблоны — `QN_COND` в app.js).
  - **«Boshqa» со своим ответом.** У вопроса с одним или несколькими вариантами вариант «Boshqa», «Boshqa (yozing)»,
    «Другое», «Other» или «其他» (без регистра, `QN_OTH_WORDS`): выбран — под вариантами строка «Yozing…» (курсор сразу в
    ней), свой ответ до 200 знаков — `answers[<id>__other]`. Сняли вариант или вопрос скрыт условием / [maxfiy] без
    согласия — свой ответ не хранится (`qnAnsOut`); обязательный вопрос с «Boshqa» без текста — «Boshqa variantni yozing»
    (кроме закрытого пункта теста в уже отправленной анкете: его поле не правится, остальное сохраняется).
    В карточке, таблице «главное», CSV и ИИ (через `qnScrub`) — «Boshqa: <текст>». Если «Boshqa» ведёт вопрос по условию
    `[agar: Boshqa]` — поля нет, свой ответ пишут в том вопросе, как раньше (`qnOthOpt`); в редакторе у варианта со своим
    полем — пометка «o‘z javobi bilan».
  - **Редактор на 100+ вопросов.** Раздел сворачивается в строку «§ Shaxsiy ma’lumotlar · 10 savol» — стрелкой слева или
    щелчком по строке раздела; у «Savollar» — «Hammasini yig‘ish / Hammasini yoyish». Новый, перенесённый или ошибочный
    вопрос раскрывает свой раздел. Колонку «Xodim shunday ko‘radi» можно скрыть — редактор шире. Свёрнутое помнит этот
    браузер (`localStorage`: `lor-qn-fold`, `lor-qn-prev`). Поле вопроса — высотой по тексту (`field-sizing: content`).
    Файл или текст при непустой анкете — выбор **«Qo‘shish (oxiriga)»** или **«Almashtirish (hammasini)»**. Замена
    спрашивает подтверждение (сколько вопросов уйдёт; ответы тех, кто уже отвечал, не удаляются, но к новым вопросам не
    привязаны — в результатах не видны, на новые вопросы отвечают заново) и берёт из текста вопросы, шкалы, темперамент,
    название и вступление (нет в тексте — прежние); «avval anketa» — из `@birinchi` или как было, «yoqilgan» — как было.
    Сохраняет только «Saqlash». Обычно: анкета — «Almashtirish», тест следом — «Qo‘shish» (`qnReplace`, `qnAppend`).
  - **Тест после анкеты** (например, «Temperament testi»: 50 утверждений, 1–5) — той же загрузкой текста, дописывается в
    конец анкеты. У раздела: `[shkala: Название]` — оценки раздела идут в шкалу; `[temperament: sangvinik |
    xolerik | melanxolik | flegmatik]` — шкала = стиль темперамента (`temper: { mode: 'max', map }`), склонность — по
    средним шкал (см. «Подсчёт и профиль» ниже); шкала без темперамента (надёжность) — отдельно;
    `[chegaralar: 10 Past | 24 O‘rta | …]` — свои границы. Строки `> …` — пояснение (не вопрос, показывается карточкой);
    `@baho: A | B | C | D | E` — подписи оценок; `@chegaralar: …` — границы по умолчанию. У вопроса теста: `[shkala: Nomi]` —
    своя шкала (шкалы можно перемешать в одном разделе), `[teskari]`, и пометки для «Качества ответов» (ниже):
    `[diqqat: 2]`, `[tekshiruv]`, `[samimiylik]`, `[juft: N]`. Оценка с подписями — шкала
    «не про меня ←→ про меня»: пять кружков, крайние крупнее, слева красные, справа синие, под ними выбранная подпись.
    Кто анкету уже отправил, а тест добавили позже, — при входе сразу на пояснение теста (дальше по шагам). В редакторе:
    способ темперамента («по самой высокой» / «экстраверсия × нейротизм»), темперамент у каждой шкалы, подписи оценок.
  - **ИИ-анализ** (нужен `ANTHROPIC_API_KEY` в Railway → Variables; без ключа — подсказка, где его задать). ИИ
    **пересказывает измеренное, а не угадывает характер** (`qnAiPrompt`, версия запроса `QN_AI_V`):
    **по человеку** — готовится сам, когда CEO / SOP-менеджер открыл карточку, а вывода нет или он устарел (ответы новее,
    прежняя версия запроса — «eskirgan»): пересказ посчитанного теста (`profile`; теста нет — «test o‘lchanmagan», о
    характере ничего), кратко, сильные стороны, на что обратить внимание, что развивать, советы руководителю — **у каждого
    пункта основание** (`evidence`: шкала и балл или вопрос и ответ; без него пункт отбрасывается, `qnAiClean`), мотивация,
    общение, **пояснение по шкалам** (`scales`: по фразе на шкалу), **подходящие виды работ** (`roles`: 2–4 вида задач в
    логистике с основанием — «попробовать на деле», не должность и не уровень), **что проверить на собеседовании или в
    работе** (`verify` — вместо прежнего «соответствия должности»), помощь в адаптации (только сотрудникам), **4 вопроса
    для собеседования** о прошлом поведении («… bo‘lgan holatni aytib bering») — у каждого «Nima uchun» (основание) и
    «Javobda nimaga e’tibor bering» (`interview: [{ q, why, listen }]`, версия запроса 3). Разница шкал меньше 0,5 — не
    различие; должности, уровни (Junior/Middle/Senior/Lead) и «выгорание» ИИ не пишет. В запросе — запреты: медицинские

    лидерства по темпераменту, сравнение людей, общие «барнумовские» фразы; предложения с медицинскими словами страница
    ещё и вырезает. Пометки о качестве ответов («Качество ответов» ниже) — готовым списком `notes`, только чтобы снизить уверенность.
    На экране — **«AI qoralamasi: o‘z-o‘zini baholash javoblari asosida, xato bo‘lishi mumkin»**, кто готовил и версия
    запроса; **«Rad etish»** (CEO и SOP-менеджер) удаляет текст, остаётся отметка (`qaReport: { off, offBy, by, v }`), сам

    **Минимум данных** (`qnAiAns`): не уходят скрытые ([maxfiy]), согласия, скрытые условием вопросы и поля профиля (имя,

    текстовом вопросе без `[sana]` (нет года — ответа нет); из текста убираются имя человека (слова от 3 букв из карточки
    и профиля, с окончаниями — «[ism]»), паспорт или ID («AA 1234567» — «[pasport]»), телефоны, почта, @-ники и ссылки на
    мессенджеры (`qnScrub(s, u)`; в анализе коллектива — то же). **Согласие на ИИ** (`qnAiAllowed`):

    вывод не показывается); у анкет без поля согласий — тоже нет (см. «Согласие» ниже). Случайность генерации не снижена: действие сервера `ai` параметра
    `temperature` не принимает. **«Har bir xodim uchun AI xulosa (n)»** — всем без вывода по очереди;

    как сотрудники описывают себя, сильные стороны, пробелы в навыках и ролях для обсуждения, где проверить сильные
    стороны, риски, шаги — без «баланса темпераментов» и «кого нанять». В запрос — люди номерами (#1 — должность, отдел,
    шкалы, главные ответы без скрытых и контактов), **без прежних выводов ИИ по каждому**; на экране номера → имена.
    Хранится в карточке того, кто готовил (`users[].qaTeam`, с `v`), — чужие карточки сотрудникам не уходят (`PUBLIC_USER`);

    руководства, кроме своей, он не меняет).

    выключены; анкета обязательна — снова «к заполнению», первым шагом согласие. **Выводы ИИ без согласия на ИИ не

    SOP-менеджера при заходе (`qnAiGone` / `qnAiPurge` в `AdminApp`; SOP-менеджер — только свою карточку руководства).

    заполнению» (`qnDue`) — при входе спрашивают **только согласие** (`qnConsOnly`; ответы остаются, на главной —
    «Anketa yuborilgan — rozilikni tasdiqlang»); до согласия ответы на [maxfiy] у CEO / SOP закрыты («Maxfiy javoblar
    yopiq», в CSV — пусто), прежний вывод ИИ сервер удаляет; у CEO / SOP — «rozilik so‘ralmagan». У CEO и SOP-менеджера: плашки «✓ AI · ✕ Maxfiy» в таблице и списке, в карточке — строкой приглушённых плашек под
    шапкой (см. ниже), в CSV — столбец «Rozilik». Автоудаление через 3 дня после отзыва обработки или закрытия цели — пока вручную
    (удаление сотрудника).

    **«Temperament shabloni»** создаёт три шкалы опросника типа Айзенка (экстраверсия, нейротизм, искренность) с границами

  - **Подсчёт и профиль** (`qnScore`, `qnTemperAll`; пороги условные, до расчёта точности шкал — см. `QN_SEM`). Балл
    шкалы — **среднее 1–5 по отвеченным** пунктам (варианты с баллами растягиваются на 1–5): пропуск не занижает шкалу;
    отвечено < 80% пунктов — **«kam javob»**, шкала не толкуется. Границы `bands` писали по сырой сумме — их сравнивают
    со средним, растянутым на сырой размах (у оценок 1–5 — среднее × число пунктов), так старые границы работают.
    Склонность, а не тип: в режиме «max» средние темпераментов по убыванию, Δ = 0,5 (`QN_DELTA`): m1 − m2 ≥ Δ —
    **«Yetakchi moyillik: ko‘proq … uslubi»**; иначе m1 − m3 ≥ Δ — **«Aralash profil: … va …»** (без основного и
    дополнительного); иначе — «Aniq yetakchi moyillik yo‘q»; m1 < 3,5 — ещё «hech bir moyillik kuchli emas»; ничьи
    порядком шкал не решаются. В режиме «en» ближе 10% размаха шкалы к средней точке — **«Turlar oralig‘ida»**.

    данные — `qnProfRows`, `qnTeam`). Карточка — **«Profil»**: полоса на шкалу на общей оси 1–5 (сетка на 2–3–4),
    значение у конца («4,1»), тень погрешности ±0,3 (`QN_SEM`, заглушка: когда наберётся ~50 заполнений — SEM по каждой
    шкале); шкалы темперамента — по порядку анкеты (карточки сравнимы), «Ishonchlilik» (в «en» — искренность) — под тонкой
    чертой. Ведущая склонность — **синим** (aralash profil — обе шкалы), остальные — серым; нет явного лидера, «kam
    javob», режим «en» — все серые (выделять нечего); в анкете нет темперамента — все синие. Под графиком — шкалы
    списком: вывод границы и 2–3 ответа, сильнее всего сдвинувших балл, — за кнопкой **«Javoblar (3)»**; и постоянная
    оговорка «O‘z-o‘zini baholash so‘rovnomasi… Xodim bilan muhokama qiling». **По коллективу** — от `QN_TEAM_MIN` (5)
    человек с посчитанным тестом, меньше — подсказка «kamida 5 kishi…» (среднее мало что говорит, человека легко узнать):
    средние шкал на той же оси с «усами» от меньшего до большего балла (по тем, у кого шкала толкуется; шкала, где таких
    меньше 5, — без полосы) и распределение склонностей — у скольких каждый ведущий стиль, «aralash profil», «aniq
    yetakchi moyillik yo‘q» (в «en» — «turlar oralig‘ida»), «kam javob». Цвета — только токены (`--blue`, в тёмной теме
    `--blue-text`; `--gray`, в тёмной — вполовину прозрачный; сетка `--line`: в широком блоке — сквозная по группе, на
    телефоне, где имя над полосой, — у каждой полосы своя, не по именам), значения подписаны у полос, у каждого
    графика — `role="img"` с подписью числами и скрытая таблица; полосы вырастают при открытии (при «уменьшить движение» —
    сразу). В таблице людей — «yetakchi moyillik / aralash profil» словами, без цветного ярлыка и без сортировки по нему.

    (меню → «Xodim savolnomasi», после отправки) видит свой профиль шкал с той же оговоркой — без вывода ИИ. В CSV и в
    запросе к ИИ — те же средние и склонность словами.

    тестов перенастроить по своим данным — жёлтый ≈ 95-й, красный ≈ 99-й процентиль, `meanD` не ниже 1,2). Проверяются
    ответы, а не человек; пункты теста 1–5 в порядке показа. **Время**: окно анкеты пишет время между ответами на пункты
    теста — только пока вкладка видна, паузы > 5 мин не в счёт, первый ответ захода без времени — и сколько раз меняли
    ответ: `users[].qa.meta = { rt: { <id>: мс }, changes }` (вместе с ответами). **Пометки вопроса** (редактор и текст):
    тип «Diqqat savoli» (`attn`, `[diqqat: 2]` — оценка 1–5 с верным ответом `expect`, в баллы не входит); «Tekshiruv»
    (`infreq`, `[tekshiruv]` — «почти никто не скажет 4–5»: «4–5» — ошибка, «3» — пол-ошибки, в баллы не входит); пара

    тексте `[juft: N]` — вопрос с номером «N.» этого текста, без номеров — N-й вопрос); «Samimiylik» (`sd`, `[samimiylik]`

    больше 20% ответов — жёлтый; серия одинаковых ≥ 10 / ≥ 15; доля «3» ≥ 60% / ≥ 90%; пары `d = |a − (6 − b)|`: `meanD` ≥ 1,2
    или `gross` (d ≥ 3) ≥ 3 — жёлтый, ≥ 1,5 или ≥ 4 — красный; согласие со всем `|acq|` ≥ 0,6 / ≥ 1; ошибки внимательности
    0,5–1 / ≥ 1,5; красный — хоть один красный или три жёлтых. Чего не посчитать (у старых ответов нет времени, пар меньше
    3, ответов меньше 10, проверок нет) — пропускается, и это написано («Tekshirilmadi: …»). Утверждения одной шкалы
    стоят подряд (10 и больше — раздел «# … [shkala: …]», так тест вставляется по умолчанию) — серия одинаковых не
    судится (пропуск «order»: у честного человека она ожидаема); чтобы серия проверялась, утверждения перемешать. «Слишком хорошо»: «5» у 4 из
    6 — пометка «Juda ijobiy o‘z-o‘zini ta’riflash — suhbatda aniqlang», в светофор не входит и из баллов не вычитается.
    **Где видно**: в карточке человека у CEO, SOP-менеджера и руководителя — рядом с результатом теста **одной строкой**
    (`QnQual`, корень `.qn-qual`): точка цвета, уровень словами («Odatdagidek / Ehtiyotkorlik bilan talqin qiling / Profil
    talqin qilinmaydi»), самая важная причина в несколько слов (`qnQTop` / `qnQShort`: «diqqat savollarida xato: 2 / 2»,
    «yana 2 ta») и справа «Batafsil»; под строкой — коротко «слишком хорошо», «Testni qayta topshirish so‘ralgan» и
    первая попытка. «Batafsil» раскрывает все причины (1–3), что не проверено (списком), сырые показатели и оговорку; в
    печати раскрыто, показатели — только на экране. Ничего не посчитано (тест короче 10 ответов, без времени, пар и
    проверок) — одна приглушённая строка «Javoblar sifati tekshirilmadi: …»; в таблице и списке — маленькая плашка у склонности (сортировки по ней нет), в
    CSV — столбец. Цвета — фирменные: норма синим, «осторожно» — красным кольцом, «не толкуется» — красным. Красный —
    кнопка **«Testni qayta topshirishni so‘rash»** (не руководителю; один раз): ответы теста и их время уходят в
    `qa.prev`, анкета остаётся, `qa.retake` — анкета снова «к заполнению» с первого раздела теста и пояснением; после
    отправки — `qa.retakeAt`, в карточке «Birinchi urinish (…)»; журнал — `qn-retake`, `qn-retake-done`. Автоматического
    отказа нет никогда. Готовые пометки (жёлтый / красный, «слишком хорошо») уходят в ИИ списком `notes` — только чтобы
    снизить уверенность; сами пункты на внимательность и проверки в ИИ не уходят. После отправки ответы теста в окне
    анкеты **только смотреть** («Test javoblari yuborilgan — ularni o‘zgartirib bo‘lmaydi»): пройти тест заново — лишь по
    «Testni qayta topshirishni so‘rash» (иначе правка обошла бы время ответов, счётчик изменений и `qa.prev`); остальные
    ответы анкеты поправить можно. **Сотруднику**: 5 ответов подряд
    быстрее 1 с — мягкая подсказка под вопросом «Har bir fikrni o‘qib chiqing — shoshilmang» (ничего не блокирует);
    перед первым вопросом шкал темперамента (или первым пунктом теста) — **честное предупреждение** (`testWarn`:
    редактор «Test oldidan ogohlantirish»; пустой текст — стандартный из отчёта на языке сотрудника, `false` — выключено).
  - **Вывод ИИ** («AI xulosa tayyorlash», нужен ключ Claude API на сервере): см. «ИИ-анализ» выше; на языке
    интерфейса. В запросе — только должность и отдел, без имени и контактов. Хранится в `users[].qaReport`; **сервер (v14) не отдаёт его самому
    сотруднику и не даёт ему записать** (`ownCard_`, `LOCKED_USER`). Сотрудник в окне анкеты видит, что ответы смотрят
    CEO, SOP-менеджер и руководитель, чтобы лучше его узнать. Везде пометка: самоотчёт, склонности, а не способности;
    сам по себе не основание для найма, увольнения или оплаты.
- **Должности и отделы** («Xodimlar» → **«Lavozim va bo‘limlar»**, `settings.positions` / `settings.depts`). Список ведёт
  **CEO**: добавить (Enter или «+ Qo‘shish», одинаковое название не пройдёт), переименовать — пока никто не занят,
  убрать — карточки сотрудников не меняются; значения у сотрудников, которых нет в списке (например, из Excel), —
  добавить одним кликом. SOP-менеджер и руководитель видят список только для просмотра; сервер (v15, `orgTouched_`)
  не принимает правку списка ни от кого, кроме CEO. Пока список не задан — стандартный (`STAFF_POS` / `STAFF_DEP`).
  Список используют: новый сотрудник и его карточка, импорт из Excel (по умолчанию и образец), кто проходит главу,
  условия зарплаты по должностям.
- **Зарплата: фикса + KPI** («Maosh»). Ведёт её **CEO**, руководитель только смотрит, SOP-менеджер её не видит
  (ни вкладки, ни сумм, ни уведомлений). CEO во вкладке «Shartlar» задаёт условия для должностей: фиксу,
  KPI-бонус при выполнении на 100 % и показатели. Каждый показатель — откуда факт (вводит сотрудник или берётся
  с платформы: опоздания, неявки, приход вовремя, часы учёбы, сданные уроки, XP, сверхзадачи, ошибки за месяц) и как
  считается: **план/факт** (доля бонуса по весу; порог — ниже него 0, потолок, «меньше — лучше»), **за единицу**
  (ставка, минус — вычет) или **премия за условие**. Во вкладке «Xodimlar» человеку можно поставить другие условия
  или свою фиксу. Сотрудник видит только свои условия, вводит факт, видит, как посчитана каждая строка, и отправляет
  расчёт с комментарием. **Каждый расчёт записывается**: пауза в наборе — попытка; ушёл со страницы, вкладки или месяца,
  не отправив, — попытки уходят в историю как «Yuborilmagan» (сотрудник предупреждён: «каждый расчёт виден
  CEO»). История — у него своя, у CEO и руководителя («Tarix») всех: сводка «Kim qancha hisobladi» (сколько
  расчётов, сколько отправлено, когда последний, последняя сумма; клик — только этот человек) и лента по дням —
  кто, когда, с какими цифрами и как посчитал, со всеми попытками. Цифры платформы сверяются с сегодняшними данными
  (⚠, если разошлись). CEO подтверждает или
  возвращает расчёт с комментарием (сотруднику — уведомление и Telegram), выгружает историю в Excel. Формула одна —
  `lms-pay.js`: сервер пересчитывает каждый сохранённый расчёт и не принимает сумму, которая не сходится с условиями.
  Расчёт в истории сотрудник не меняет и не удаляет; за месяц — до 20 отправленных и 40 неотправленных (в каждом —
  до 40 попыток, каждую сервер тоже пересчитывает). Суммы — только на сервере.
- **Что видит сотрудник:** правильных ответов тестов нет ни у кого, кроме SOP-менеджера. Закрытые разделы — только
  названия уроков, до конца испытательного срока. Чужие анкеты, опросы, заявки и уведомления скрыты. Про коллег
  он видит только то, из чего считается рейтинг: должность, уровень, статус и балл уроков, минуты учёбы.
  Журналы и термины — по правам доступа, которые задал SOP-менеджер, кейсы — только опубликованные.
- **Что сотрудник может менять:** только своё — анкету, план адаптации, «читаю / вопрос / готов к тесту» в уроке,
  свои заявки, идеи, опросы, отметки «ознакомлен», сообщение о проблеме со своим имуществом. Уровень, статус, итог урока,
  отметки шкалы уровня, сверхзадачи, курс меняет SOP-менеджер. Балл теста и повторной проверки после ошибки считает
  сервер (`quiz`, `retest`). Наставник ещё записывает ошибки подопечным. Каждая отклонённая правка возвращается
  с причиной, страница показывает её внизу слева.
- **Профиль** («Mening profilim» в меню под именем): фото (уменьшается до 128×128 и хранится в данных), имя и логин
  каждый меняет сам — логин с текущим паролем. **Пароли:** CEO — всем, SOP-менеджер — только сотрудникам
  (решение владельца 14.10.2026): «Xodimlar» → «Tahrirlash» (там же имя, логин, должность, отдел, фото) или
  «Parolni tiklash». Свой пароль в профиле меняют CEO, SOP-менеджер и руководитель.
- **Удаление сотрудника** («Xodimlar» → «Tahrirlash» → **«Xodimni o‘chirish»**, CEO и SOP-менеджер; руководитель только
  смотрит). Окно подтверждения говорит, что уйдёт и что останется, предупреждает о невозвращённом имуществе и
  напоминает скачать копию («Ma’lumotlarni yuklab olish»); без галочки «Tushundim» кнопка закрыта. Вход закрывается
  сразу: сервер стирает учётную запись и все сессии (`syncCreds_`), файлы карточки — скан паспорта — уходят в корзину
  Диска, если на них больше ничто не ссылается (v16, `dropGoneFiles_`). Удаляются карточка с профилем и анкетой
  («Savolnoma»), прогресс, время учёбы, уведомления и обращения (`deleteUser`). Остаются: зарплата, посещаемость,
  имущество, идеи, сверхзадачи, опросы и журнал (`audit`: `user-deleted`). Итоги обучения (если сдан хоть один урок)
  можно оставить в рейтинге среди «прежних кандидатов» (`alumni`: имя, должность, цифры). Восстановить нельзя —
  только создать заново.
- **Сотрудники в Excel и Google Sheets** («Xodimlar» → блок «Excel jadvali»):
  - «Excelga yuklab olish» — файл `buraq-xodimlar-<дата>.xlsx` с листами **Xodimlar** (ID, F.I.Sh., Login, Lavozim,
    Bo‘lim, Telefon, Telegram, статус, уровень, программа, XP, анкета), **Natijalar** (уроки: статус, балл, дата)
    и **Rahbarlar** (адресаты идей). Открывается в Excel; в Google Sheets — загрузить на Google Диск, откроется таблицей.
    В файле личные данные из анкеты (паспорт, адрес) — не пересылайте его куда попало.
  - Правки — на листе Xodimlar, потом «Faylni tanlash» (.xlsx или .csv; из Google Sheets — «Файл → Скачать → .xlsx»).
    Строка **с ID** обновляет этого сотрудника: имя, логин, должность, отдел, телефон, Telegram и пароль (столбец
    Parol, если добавить); пустая ячейка оставляет как было. Столбец **Holat** («Rasmiy» / «Sinov», по-русски «Штатный» / «Испытательный») задаёт статус; пусто — как было,
    новый — «Sinov muddati». Строка **без ID** — новый сотрудник: пустые логин и пароль
    создаются сами (логин из имени: «Dilnoza Karimova» → `d.karimova`, кириллица → латиница). Перед сохранением
    страница показывает, что изменится в каждой строке; занятый логин — отказ в этой строке. Остальные столбцы и листы
    при загрузке не читаются. Заголовки — по-узбекски, по-русски или по-английски; есть «Namuna fayl».
  - После сохранения новых — «Login va parollarni yuklab olish»: раздайте и удалите файл.
  - Таблица — выгрузка, а не живая связь: данные хранятся на сервере, файл — снимок на момент скачивания.
- **Приход на работу в программе** (действие `clock`, сервер v13). При открытии программы сотруднику, который ещё не
  отметился, показывается **модальное окно «Ishni boshlaymizmi?»**, а наверху «Bosh sahifa» висит красная плашка
  «Bugun ishni boshlamadingiz», пока приход не отмечен. Сотрудник нажимает **«Ishni boshlash»**, в конце дня на карточке
  «Ishga kelish» — **«Ishni tugatish»**; **время ставит сервер** (Ташкент, UTC+5 — подделать нельзя), запись
  `attend[uid][день] = { in, out, src: 'app' }` — тот же формат, что у выгрузки турникета, поэтому в «Monitoring» и
  в зарплатных KPI она учитывается без изменений. Нельзя отметить дважды, отметить уход раньше прихода или переписать
  день, уже закрытый турникетом. SOP-менеджер выключает отметку на «Xodimlar» («Xodimlar ishga kelishni dasturda
  belgilaydi»).
  - **Без камеры и снимков (сервер v17, решение владельца «delete face control»).** Окно только спрашивает
    «Ishni boshlaymizmi?» и отмечает время; камера не включается, фото не делается и не показывается — ни сотруднику,
    ни в «Monitoring». Причина: фото лица может считаться биометрией, а её по закону Узбекистана (ЗРУ-1125 с 27.03.2026)
    нельзя хранить вне страны — сервер на Railway. Окно всегда закрывается («Keyinroq»), чтобы никого не запереть;
    личность подтверждена входом по логину и паролю. Поле `photo` от страницы, открытой до v17, сервер не читает;
    правку записи прихода или карточки с полем снимка (`inPhoto`, `outPhoto`, `faceEnroll`, `facePhoto`) не принимает,
    а снимок внутри записи прихода целиком (старая страница SOP-менеджера) убирает.
  - **Очистка старых снимков — один раз** (`facePurge_` в `migrate_`, флаг `settings.facePurgedV`). При каждом чтении
    данных, пока очистка не записана, сервер убирает снимки из записей прихода (вместе с прежней версией `prev`) и поля
    сверки лица из карточек — снимков сразу не видно, и файл больше не отдаётся (`file_`). Файлы снимков
    (`lmsfile:<id>`) уходят в корзину Диска после записи данных без ссылок на них (`faceTrash_`); файл, на который
    ссылается что-то ещё, остаётся. Сервер на Node (Railway) делает это при запуске (`purgeFaces`, в журнале «Снимки при
    отметке прихода удалены…» — файлы удаляются с диска сразу). В Apps Script — при первой же правке или вручную
    (▶ Выполнить → `purgeFaces`); там файлы лежат в корзине Диска ещё 30 дней — чтобы убрать сразу, очистите корзину.
    В ночных копиях `backups/` до очистки остались только ссылки, самих снимков там нет. **v18** (`FACE_PURGE_V` 2 —
    очистка ещё раз): и файлы-снимки, на которые ссылок уже нет (до v17 снимок сохранялся до проверки «приход уже
    отмечен»; запись прихода со снимком могли стереть или заменить правкой), — все файлы с именем `ishga-kelish` в папке
    `files`, на которые в данных нет ссылки.
- **Профиль после анкеты — без повторов** (`qnProfileX`, `splitFio`): если анкета отправлена, в «Xodim anketasi» скрыто то,
  что в ней уже есть (имя — фамилия по окончанию -ov/-ev/-ova…, дата рождения, телефон, Telegram, адрес, контакт на крайний
  случай, образование из «Ma’lumotingiz», языки из таблицы уровней, кроме «Bilmayman»), и необязательные поля; шаг, где
  ничего не осталось, пропускается. Обычно остаются паспорт (номер и скан) и стаж. Если не осталось ничего — анкета
  закрывается сама. **Имущества в анкете нет** (с сервера v22): его выдаёт SOP-менеджер, сотрудник принимает на «Mol-mulk».
- **Скан паспорта хранится 48 часов** (сервер v19, `ppTrack_` / `ppExpire_` / `ppSweep`). Время загрузки ставит сервер
  (`profile.passportFile.at`; сотрудник его не продлит — при прежнем файле поля берутся из сервера). SOP-менеджерам (нет SOP —
  CEO) — уведомления, в том числе в Telegram: «загружен, скачайте за 48 часов» (`pp`), за 12 часов, если ещё не скачан
  (`pp-warn`), «удалён, скачан / не скачан» (`pp-gone`). Скачивание из таблицы «Xodimlar» отмечается (`dlAt`, `dlBy`), там же —
  сколько часов осталось. Через 48 часов файл уходит в корзину Диска, в профиле — `passportGone` (в анкете — «Skan
  yuborilgan», повторно не требуется). Проверка сроков — при каждой правке и раз в час на сервере Node; в Apps Script —
  триггер по времени на функцию `ppSweep` (с v20 `installTriggers` ставит его сам, раз в час). Сканы, загруженные до
  v19, получают срок 48 часов с момента обновления сервера. С v20 прежний скан, который заменили новым или убрали,
  уходит в корзину сразу (в Apps Script корзина Диска хранит файл ещё 30 дней — её можно очистить вручную).
- **Скан паспорта** в анкете SOP-менеджер выключает на странице «Xodimlar» («Anketada pasport skanini so‘rash»).
- Пароль в карточке сотрудника сервер переносит в учётную запись и из данных убирает; удалённый сотрудник сразу
  теряет вход.
- **Идеи (tashabbus)** сотрудник отправляет одному или нескольким адресатам: CEO, Project Manager, руководителю компании
  (хотя бы один обязателен, потом не меняется). Каждый адресат видит идеи, где он среди адресатов, ставит статус
  и пишет ответ (ответ у идеи один — отвечает любой из адресатов, автор видит, кто); автор получает уведомление и XP
  за принятую идею. Идеи, адресованные другим, не читает никто, кроме адресатов: сервер отдаёт только статус и даты
  (из них считаются XP и уровни) и не даёт их менять. Старые идеи без адресата видят и отвечают на них CEO
  и SOP-менеджер.

### «Fayldan qo‘shish» — Keyslar, Jurnallar, Terminologiya

- Кнопка «⇪ Fayldan qo‘shish» рядом с «+ Yangi …» во вкладках «Kontent». Файл читается в браузере (`siRead`): Excel
  (.xlsx), CSV/TSV, Word (.docx — абзацы, заголовки и таблицы), текст (.txt/.md). Сначала просмотр с галочками,
  добавляется только отмеченное; «Qoralama» (по умолчанию) или «Darhol e’lon qilish» — неполное (у термина определение
  короче 20 знаков, у кейса нет ситуации или вывода) всё равно остаётся черновиком, об этом говорит сообщение.
- **Термины** (`siTerms`): таблица — столбцы по заголовку (Atama / Qisqa / Ta’rif / Toifa, по-русски и по-английски тоже),
  без заголовка — по порядку; текст — строки «Atama — ta’rif» или «Atama: ta’rif», заголовок с абзацем под ним. Нет
  краткого — первое предложение определения; категория — из столбца файла, иначе по словам (bojxona → customs,
  ombor → warehouse, hujjat/invoys/CMR → doc …). То, что уже есть в словаре, помечено «lug‘atda bor» и не отмечено.
- **Журнал** (`siJournal`): первая строка — названия столбцов (если она текстовая), тип столбца по значениям — число,
  дата (05.11.2026 и даты Excel → 2026-11-05) или текст; столбец с пустыми ячейками — необязательный. До 12 столбцов и
  2000 строк; название — из имени файла (можно поменять), создаётся черновиком или сразу.
- **Кейсы** (`siCases`): каждый заголовок Word (или строка «# …») — новый кейс; части «Vaziyat / Holat», «Harakatlar /
  Nima qildik», «Natija», «Xulosa / Saboq», «Xatolar» разбираются сами (действия — пунктами), остальное — ситуация;
  сфера — по словам. Если пометок нет — «✦ AI bilan ajratish»: текст (до 24 000 знаков) уходит в AI, ответ — JSON-список
  кейсов только по фактам из текста.

### Уведомления на компьютере (Windows / macOS)

- Меню профиля → **«Kompyuter bildirishnomalari»** (у всех ролей): браузер один раз спрашивает разрешение, приходит
  пробное уведомление. Выбор — на этом устройстве (`localStorage` `lor-sysnotif`).
- Пока сайт открыт в какой-нибудь вкладке (в том числе за CRM или в свёрнутом окне), новое уведомление человека — в углу
  экрана (`useSysNotify`, текст — как в колокольчике, `notifText`); SOP-менеджеру и CEO — ещё и каждая новая открытая
  заявка «So‘rovlar» («Dilnoza imtihonga tayyor — 2.1. …», «…: savol — …», доступ, уровень). Клик открывает её на сайте.
  Не больше трёх за раз, остальное — «Yana N ta yangi xabar». Если человек смотрит на сайт — только колокольчик.
- Чтобы новое дошло, когда вкладка свёрнута или открыта другая, страница при включённых уведомлениях продолжает
  спрашивать сервер «что нового» и в фоне (`LmsClient.pollTick`, раз в 30 секунд; браузер в фоне может реже — до минуты).
  Без уведомлений фоновая вкладка, как раньше, сервер не спрашивает.
- Заголовок вкладки — со счётчиком: «(3) BURAQ o‘quv platformasi» (непрочитанные + открытые заявки у SOP-менеджера).
- Когда браузер закрыт, уведомлений нет — для этого Telegram (см. «Уведомления в Telegram»).

### Mol-mulk: выдаёт SOP-менеджер, сотрудник принимает (сервер v22)

- SOP-менеджер: «Mol-mulk» → «Mol-mulk biriktirish» — сотрудник, вещь, номер, состояние, дата (статус `issued`). Сотруднику —
  уведомление и баннер на главной «Sizga N ta yangi mol-mulk biriktirildi».
- Сотрудник: вкладка «Mol-mulk» → блок «Sizga berildi — qabul qiling»: у каждой вещи «✓ Qabul qildim» (и «Hammasini qabul
  qildim (N)», если их несколько) — вещь `active`, `confirmedAt`; «Farq bor» — пояснение (`mismatch`). И то, и другое —
  уведомление SOP-менеджерам и CEO (`kind: 'asset_in'`, `assetIn: { k: 'ok' | 'diff', name, items }`, в Telegram тоже).
  «Qabul qildim» — согласие с материальной ответственностью (подпись под блоком). Вещь, которой нет в списке, — ссылкой
  «Ro‘yxatda yo‘q narsa sizda bormi? Xabar berish» (самодекларация, её подтверждает SOP-менеджер).
- В анкете шага «Mol-mulk» больше нет; кабинет открывается после трёх шагов анкеты (`profileComplete`). У SOP-менеджера
  плитка «Hammasini qabul qilganlar» и в списке по сотрудникам — «N ta qabul qilinmagan» / «hammasi qabul qilingan».

### Часы учёбы («Bugun 0:07 / 2:00» в шапке)

- Секунда засчитывается, только если всё сразу: открыт урок или его тест (или AI-mentor), вкладка видна, **окно браузера
  в фокусе** (играющее видео урока внутри страницы — тоже фокус), не включён экран защиты и сотрудник двигал мышью,
  печатал или прокручивал **за последние 2 минуты** (пока играет видео — 15). Иначе — пауза: другая страница, другое окно
  или программа (CRM, Excel, Telegram), вкладка скрыта, сайт закрыт, выход из аккаунта.
- Секунды «без движения» засчитываются, когда сотрудник снова пошевелился, переключился или ушёл с урока (он читал);
  если 2 минуты тишины — из них засчитывается только 1 минута (он отошёл). Ноутбук уснул — не больше 5 секунд.
- Неполная минута не теряется: лежит в браузере за сегодня (`localStorage` `lor-study-sec:<id>`) и идёт дальше в следующий
  раз; целые минуты уходят на сервер (`study[id][день]`, как раньше). Две вкладки не считают дважды: идёт только та,
  что в фокусе, и только она пишет секунды.
- В шапке у часов точка: **красная, пульсирует — время идёт**; серая — пауза. Неожиданная пауза (другое окно, вкладка
  скрыта, 2 минуты без движения) — ещё и «· pauza»; причина — в подсказке (`st_run`, `st_page`, `st_hidden`, `st_away`,
  `st_idle`). Состояние — маленький общий стор `STUDY`: каждую секунду перерисовываются только часы, не страница.

### Защита материалов: сотрудник только смотрит

У сотрудника (`role: 'employee'`; SOP-менеджер, CEO и руководство — как раньше) App ставит `GUARD` и рисует `Guard`:

- **Скачать нечего.** PDF знакомства — страницами-картинками (`PdfPages`), без ссылки на файл; бланки журналов
  открываются в просмотре (`DocViewer` без «Yuklab olish»; формат не PDF/DOCX — «нельзя показать на сайте»); у своего
  файла в доп. задании — только название; видео `.mp4` — без «скачать» и «картинка в картинке» (`controlsList`).
  Свой скан паспорта сотрудник по-прежнему открывает — это его документ.
- **Не сохранить и не напечатать.** Ctrl/Cmd+S и Ctrl/Cmd+P отменены (подсказка «Materiallarni saqlash…»), печать из меню
  браузера даёт пустой лист (`@media print`), правая кнопка, копирование и перетаскивание закрыты — кроме полей ввода;
  выделение текста выключено (`html.emp-guard`).
- **Водяной знак** поверх всех экранов (`.grd-wm`, цвет — токен `--watermark` с `opacity: .3`, ≈3 % — глазу почти не
  виден, на снимке проявляется при увеличении контраста): «имя · логин · дата» по диагонали, редко. Любой
  снимок или фото экрана показывают, чей это экран, — это и есть главная защита от снимков.
- **Попытка снимка закрывает экран** (`.grd-cover`, синий, с логотипом): PrintScreen (и буфер обмена очищается),
  Win/Cmd+Shift (Ножницы Win+Shift+S, снимки macOS Cmd+Shift+3/4/5), печать — до нажатия «Davom etish uchun bosing»;
  уход в другое окно или вкладку (Ножницы с задержкой, запись экрана) — пока окно не вернётся. Клик во встроенное видео
  уходом не считается.
- **Попытку снимка видят CEO и SOP-менеджер** (`shotReport`): уведомление «{name}: попытка снимка экрана (PrintScreen /
  Win+Shift+S / Cmd+Shift+3/4/5)» каждому CEO и SOP-менеджеру (и в Telegram), сотруднику — своё «попытка записана, CEO и
  SOP-менеджер получили уведомление»; на синем экране — красная строка «Urinishingiz qayd etildi». Сервер не менялся:
  уведомить других о своём действии сотрудник может и раньше, `from` ставит сервер. Попыткой считается PrintScreen и
  Win/Cmd+Shift, после которых до страницы не дошла другая клавиша (её забрала система — S, 3, 4, 5) и вкладка не скрылась
  (Cmd+Shift+T, N, [ ] — не снимок); одна запись в минуту. Снимок из меню macOS, Lightshot, PrtSc в Windows 11 (сразу
  «Ножницы»), телефон браузер не видит — о них уведомления не будет, остаётся водяной знак.
- **Предел сайта:** снимок экрана на телефоне, фото экрана другим телефоном, программы записи без фокуса браузер не видит
  и запретить не может — для них водяной знак. Тексты стандартов и так не в репозитории, а на сервере.

### Роли и доступ

Решение владельца 14.10.2026. Уровень задаёт карточка в данных: `role` и `post` (`lvl_` в `tools/lms-gs/Server.gs`,
`lvlOf` в `app.js`). Каждую правку сервер проверяет сам — страница только прячет кнопки.

| | CEO | SOP-менеджер (методист) | Руководитель (владелец) | Project Manager | Сотрудник |
|---|---|---|---|---|---|
| Карточка | `admin`, `post: ceo` | `admin` | `admin`, `post: boss` | `leader`, `post: pm` | `employee` |
| Курс, 4-bob, тесты, журналы, кейсы, опросы, план, турникет | всё меняет | всё меняет | смотрит | — | своё |
| Сотрудники: карточки, Excel, анкеты | всё | всё | смотрит | — | своя |
| Входы руководства (CEO, руководитель, PM, SOP-менеджеры) | создаёт, меняет, удаляет | только первый CEO, пока CEO нет | — | — | — |
| Пароли | всем | сотрудникам (и свой) | свой | — | — |
| Зарплата: условия, подтверждение расчётов | да | не видит | смотрит | — | свой расчёт |
| Отчёты, «Ma’lumotlarni yuklab olish» | да | да (без зарплаты) | да | — | — |
| Идеи | адресованные CEO и без адресата | без адресата | адресованные ему | адресованные ему | свои |

- **Защита правок (сервер v20)** — проверки, которых раньше не было:
  - карточка человека: `id` не меняется и не повторяется (число 10901 и строка «10901» — один человек); «новая» карточка
    с занятым id не принимается — ни подменой входа CEO, ни когда два устройства выдали один номер (`usersIdBad_`);
  - тест урока — одна попытка: пока тест пройден и ждёт итога SOP-менеджера, ни балл, ни статус не сбросить; прогресс не
    удаляется (`checkLesson_` сравнивает и пропавшие поля);
  - балл в заявке на экзамен пишет только сервер; новая заявка — открытая, без балла и ответа; закрыть можно только свою
    открытую; сверхзадачу «выполнено» и ошибку «закрыта» / «повторная проверка сдана» сотрудник не поставит и целой записью;
  - имущество: выданное — «принял» или «не совпадает» с пояснением; самодекларацию подтверждает только SOP-менеджер;
  - уведомление другому — только о своём действии (попытка снимка, идея, сверхзадача на проверке, ошибка от наставника,
    ответ на идею, «Qabul qildim» по имуществу — v22), без своего текста; список уведомлений целиком не меняется, повторяющиеся id сервер разводит;
  - минуты учёбы — только за сегодня (± сутки по Ташкенту) и не больше 1440; оценка ИИ-тренировки — от 0 до 5;
  - ссылка на чужой файл не проходит и в самом пути правки; тест закрытой для человека главы не открывается.
- **Руководитель** входит в тот же кабинет, что и CEO, со всеми разделами и отчётами, но в режиме просмотра:
  вверху полоса «Ko‘rish rejimi», кнопки правок скрыты, а если правка всё же уйдёт — страница отвечает «Faqat
  ko‘rish», сервер её не принимает. Сам он меняет только свою карточку (имя, фото), свои уведомления и ответы
  на идеи, адресованные ему («Fikrlar»).
- **Как начать:** SOP-менеджер (вход из журнала Railway) в «Xodimlar» → «CEO kirishini yaratish» создаёт вход CEO —
  только один раз, пока CEO нет. Дальше входы руководства ведёт CEO: «Xodimlar» → «Rahbariyat kirishlari» —
  CEO, руководитель, Project Manager, ещё SOP-менеджеры; там же новые пароли.
- Прежние входы адресатов идей с должностью CEO или «руководитель» (`leader`) сервер при чтении данных переводит
  в новые уровни (`migrate_`): логины и пароли те же. Project Manager остаётся адресатом идей.

### ИИ (Claude API)

Наставник, разбор кейсов, опросы и редактор курса обращаются к Claude через сервер: ключ лежит только на сервере
и на страницу не попадает.

1. [platform.claude.com](https://platform.claude.com) → войдите (лучше под тем же аккаунтом компании) → **Billing** —
   пополните баланс → **API keys → Create key** → скопируйте ключ `sk-ant-…`.
2. **Railway:** сервис → **Variables → New Variable**: `ANTHROPIC_API_KEY` = ключ → Railway перезапустит сервис сам.
   **Apps Script:** **⚙ Настройки проекта → Свойства скрипта → Добавить свойство** `ANTHROPIC_API_KEY` = ключ →
   **Сохранить** (новое развертывание не нужно). Страница увидит ИИ в течение 30 секунд.

Необязательные (Railway — переменные, Apps Script — свойства скрипта):

| Свойство | По умолчанию | Что меняет |
| --- | --- | --- |
| `AI_MODEL` | `claude-opus-5-5` | модель (например, `claude-sonnet-5-5` — дешевле) |
| `AI_DAILY_LIMIT` | `30` | запросов в день на сотрудника |
| `AI_DAILY_LIMIT_ADMIN` | `200` | запросов в день на SOP-менеджера |
| `AI_MAX_TOKENS` | `4096` | длина ответа |

- Если основная модель отказывает в ответе, Claude API сам повторяет запрос на запасной модели (`fallbacks`).
- Сколько запросов сделал каждый за сегодня и сколько токенов ушло — свойство `AI_USAGE` (день по Ташкенту;
  на Railway — в `props.json` на томе).
  Цены — на [platform.claude.com](https://platform.claude.com) → **Usage / Cost**; там же можно поставить месячный
  лимит расходов.
- Лимит исчерпан — «Bugungi AI so‘rovlari limiti tugadi», ключа нет или он неверный — «AI hali ulanmagan».

### Видео уроков

Ролики — на YouTube того же аккаунта с доступом **«По ссылке»** (YouTube Studio → «Создать» → «Добавить видео» →
«Параметры доступа» → «По ссылке»). Ссылку — в урок: «Kontent» → урок → поле «YouTube havolasi» → «Saqlash».
Урок показывает ролик через `youtube-nocookie.com`; ссылка доходит до сотрудника только после входа, поверх урока — водяной
знак с его именем. Кто получил ссылку, может её переслать — если ролики станут секретнее, их можно перенести на платный
Vimeo с показом только на этом сайте, в уроке поменяется только ссылка. Без ссылки в уроке — заглушка плеера.

### Запросы

POST на `…/exec`, тело — JSON (`Content-Type: text/plain`, чтобы браузер не делал предварительный запрос),
ответ — `{ ok: true, … }` или `{ ok: false, code, error }`.

| action | Кто | Что делает |
| --- | --- | --- |
| `ping` | все | версия сервера, настроен ли |
| `login` `{login, password}` | все | `{token, me, rev}`; коды ошибок `login`, `locked` |
| `logout` | вошедший | закрывает вход на этом устройстве |
| `load` | вошедший | `{v, rev, me, state}` — состояние, которое ему положено видеть |
| `since` `{rev}` | вошедший | `{same: true}`, если ничего не менялось, иначе как `load` |
| `patch` `{ops}` | вошедший | правки (`lms-sync.js`), `{rev, applied, rejected: [{i, reason}]}`; `data:`-файлы — на Диск |
| `quiz` `{lessonId, answers}` | вошедший | балл теста и правильные ответы — после сдачи |
| `retest` `{errorId, answers}` | вошедший | повторная проверка после ошибки (3 первых вопроса урока) |
| `file` `{id}` | вошедший | файл `lmsfile:<id>`, если ссылка на него вам видна |
| `account` `{old, login?, password?}` | вошедший | свой логин (каждый, с текущим паролем); свой пароль — CEO, SOP-менеджер, руководитель; другие устройства выходят |
| `password` `{old, password}` | CEO, SOP-менеджер, руководитель | смена своего пароля (как `account`) |
| `resetPassword` `{userId}` | CEO, SOP-менеджер | новый пароль — показывается один раз; SOP-менеджер — только сотрудникам |
| `ai` `{messages, tier, json}` | вошедший | ответ Claude `{text, truncated, model}`; коды `ai_off`, `ai_key`, `ai_limit`, `rate_limited`, `refused`, `ai_err` |

Другие коды ошибок: `auth` — нужен вход, `forbidden` — нет прав, `busy` — сервер занят записью (повторить),
`setup` — не запущен `setup`, `bad` — неверный запрос.

## Как страница работает с сервером

- `update(fn)` меняет данные, как в прототипе; `lms-client.js` считает разницу «было → стало» и кладёт её в очередь
  на устройстве, через полсекунды — на сервер пачкой. Пока правка не дошла, она видна на экране.
- Без сети правки ждут на устройстве (внизу слева — «Internet yo‘q…»), уходят сами при появлении сети.
- Раз в 30 секунд, при возврате на вкладку и при появлении сети — «что нового» (`since`).
- Номера новых записей — время и случайная часть (у двух устройств `seq + 1` совпал бы).
- Тест урока и повторная проверка — на сервере: у сотрудника правильных ответов нет, их показывают после сдачи.
- Месячный отчёт выпускает только SOP-менеджер. Журнал нарушений защиты урока обрезает сервер (последние 500).
- Язык и вход — только на устройстве.
- Открытый раздел — в адресе страницы (`#cms`, `#lesson?id=b2-1`): после обновления открывается он же, ссылку на
  раздел можно переслать коллеге с тем же кабинетом. Раздел чужого кабинета по ссылке не открывается — стартовая страница.

## Вычитка надписей

Надписи (uz, ru, en, zh) — в `strings.js`. Для носителя языка:

```bash
node tools/strings-review.mjs export matnlar.csv   # таблица: key; uz; ru; en; zh — открывается в Excel
node tools/strings-review.mjs import matnlar.csv   # исправленные ячейки — в конец strings.js отдельным блоком
```

В ячейках можно менять только текст; `{x}`, `{n}` и т. п. — оставить (иначе правка пропускается).

## Известные ограничения

- XP за опросы и ИИ-тренировки считает страница — оценку тренировки сервер ограничивает 0–5, число опросов не проверяет;
  накрутить их можно через инструменты разработчика. Итог урока решает устный экзамен у SOP-менеджера, его сотрудник не
  поставит. Ответы своей анкеты после отправки сотрудник технически может переписать (сервер этого не запрещает).
- SOP-менеджер может задать сотруднику пароль и войти под ним — так он увидел бы условия зарплаты этого сотрудника.
- Пять неверных паролей подряд закрывают вход на 15 минут любому логину, и CEO тоже: так можно на время не пустить человека.
- Все данные (кроме файлов) — один файл: каждая запись переписывает его целиком. Для десятков и сотен сотрудников этого
  хватает. Если станет медленно, файл можно разделить (курс, люди, журналы).
- Apps Script отвечает за 1–2 секунды (Railway — быстрее); вход — чуть дольше (хэш пароля).
- На Railway — один экземпляр сервиса (том подключается к одному): для сотен сотрудников этого хватает.
- Страница работы без сети не кэширует свои файлы: открыть её без интернета можно, только если браузер держит её в кэше.
  Данные и правки без сети работают.
