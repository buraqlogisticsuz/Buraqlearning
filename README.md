# Учебная платформа BURAQ (BURAQ o‘quv platformasi)

Обучение сотрудников: курс по стандартам компании, тесты и устный экзамен у методиста, план адаптации 30/60/90,
уровни, рейтинг, журналы и термины, кейсы, ошибки и наставники, сверхзадачи, опросы, учёт турникета.
Роли: **методист** (admin) и **сотрудник**; наставник — сотрудник с отметкой «наставник».

Сайт: **https://buraqlogisticsuz.github.io/Buraqlearning/** (демо — `…/Buraqlearning/?demo=1`).
Репозиторий: [buraqlogisticsuz/Buraqlearning](https://github.com/buraqlogisticsuz/Buraqlearning).
Старый адрес `…/xeeds/learn/` перекидывает сюда.

## Что где лежит

| Путь | Что это |
| --- | --- |
| `index.html` | Страница: React из `js/vendor/`, шрифты из `fonts/`, логотип из `buraq-brand/logo/`, значки из `icons/` |
| `config.js` | **Адрес сервера** (`window.LMS_SERVER = '…/exec'`). Пусто — только демо |
| `lms-client.js` | Связь с сервером: вход, данные, очередь правок, работа без сети (`window.LmsClient`) |
| `lms-sync.js` | Разница «было → стало» и её применение. Общий для страницы и сервера |
| `lor.css` | Стили (дизайн-система по бренд-буку) |
| `lor-ds.js` | Компоненты дизайн-системы (`window.LOR`): кнопки, шапка, защищённый просмотр, плеер |
| `demo-data.js` | Демо-данные (выдуманные сотрудники, прогресс, кейсы) и шаблоны: уровни, программы, план адаптации, график |
| `strings.js` | Надписи на четырёх языках: uz (основной), ru, en, zh |
| `app.js` | Приложение |
| `lms-gs-script.js` | Код сервера для кнопки «Скопировать код сервера» (собирается, не править) |
| `tools/lms-gs/Server.gs` | Сервер (Google Apps Script) |
| `tools/lms-gs/Code.gs` | Сервер одним файлом для Apps Script: `node tools/build-lms-gs.mjs` (Server.gs + lms-sync.js) |
| `tests/lms-*.test.mjs` | Тесты синхронизации и сервера: `node --test tests/` |
| `tests/lms-dev-server.mjs` | Платформа локально с сервером на заглушке Apps Script (данные в памяти) |
| `tests/lms-e2e.mjs` | Проверка в браузере (Playwright): методист и сотрудник от входа до итога экзамена |

Надписи платформы — в `strings.js` (словарь на 4 языка).

## Публикация (GitHub Pages)

1. Один раз: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. Каждый пуш в основную ветку: `.github/workflows/pages.yml` прогоняет тесты (`node --test tests/*.test.mjs`) и

## Два режима

- **С сервером** (адрес в `config.js`) — рабочая платформа: вход по логину и паролю от методиста, общие данные
  для всех устройств. Внизу страницы — «Ma’lumotlar BURAQ serverida saqlanadi».
- **Демо** — адрес пустой или ссылка `?demo=1`: прототип, данные только в этом браузере, на экране входа
  демо-входы (`metodist / admin123`, сотрудники — пароль `1234`), «Demo ma’lumotlarni tiklash» возвращает примеры.

**Тексты стандартов «4-bob» в репозиторий не попадают:** репозиторий открытый. В демо у уроков 4.1–4.20 только номера
и названия, текст — заглушка. Настоящие тексты и тесты методист загружает на сервер из файла прототипа, сотрудники
получают их только после входа.

ИИ-помощники (наставник, кейсы, опросы, редактор курса) вне claude.ai пока выключены — сервер для них будет на шаге 5.

## Сервер

Отдельный проект Google Apps Script — **не** скрипт таблицы отгрузок. Бесплатно, своего сервера не нужно.

- **Данные** — файл `state.json` в папке «BURAQ o‘quv platformasi — ma’lumotlar» на Google Диске владельца
  скрипта. Каждую ночь в 03:00 (Ташкент) — копия в `backups/state-ГГГГ-ММ-ДД.json`, копии хранятся 30 дней.
- **Файлы** — сканы паспортов из анкеты, вложения журналов и сверхзадач — в папке `files` рядом с `state.json`, в данных
  остаётся ссылка `lmsfile:<id>`. Файл сервер отдаёт только тому, кому видна эта ссылка: свой паспорт — сотруднику,
  все — методисту. (Без этого `state.json` вырос бы за пределы 10 МБ, которые Apps Script может записать.)
- **Вход** — логин и пароль проверяет сервер. Пароли хранятся только как PBKDF2-SHA256 с солью (10 000 повторов)
  в свойствах скрипта, в `state.json` их нет. После 5 неверных паролей подряд логин закрыт на 15 минут. Вход на
  устройстве живёт 30 дней с последнего запроса, у одного человека — до 10 устройств.
- **Что видит сотрудник:** правильных ответов тестов нет ни у кого, кроме методиста. Закрытые разделы — только
  названия уроков, до конца испытательного срока. Чужие анкеты, опросы, заявки и уведомления скрыты. Про коллег
  он видит только то, из чего считается рейтинг: должность, уровень, статус и балл уроков, минуты учёбы.
  Журналы и термины — по правам доступа, которые задал методист, кейсы — только опубликованные.
- **Что сотрудник может менять:** только своё — анкету, план адаптации, «читаю / вопрос / готов к тесту» в уроке,
  свои заявки, идеи, опросы, отметки «ознакомлен», сообщение о проблеме со своим имуществом. Уровень, статус, итог урока,
  отметки шкалы уровня, сверхзадачи, курс меняет методист. Балл теста и повторной проверки после ошибки считает
  сервер (`quiz`, `retest`). Наставник ещё записывает ошибки подопечным. Каждая отклонённая правка возвращается
  с причиной, страница показывает её внизу слева.
- **Методист** меняет всё. Пароль в карточке сотрудника сервер переносит в учётную запись и из данных убирает;
  удалённый сотрудник сразу теряет вход.

### Настройка (один раз, ~15 минут)

1. Войдите в Google под аккаунтом **buraqceoassistant@gmail.com** — данные платформы будут на его Диске
   (решение владельца, 10.10.2026).
2. [script.google.com](https://script.google.com) → **Новый проект** → назовите «BURAQ o‘quv platformasi».
3. Откройте на GitHub файл `tools/lms-gs/Code.gs` → **Raw** → скопируйте всё → вставьте вместо кода в редакторе →
   **Сохранить**.
4. Вверху выберите функцию **`setup`** → **▶ Выполнить** → «Проверить разрешения» → свой аккаунт → «Дополнительные
   настройки» → «Перейти к проекту» → **Разрешить** (Диск — для данных и файлов, триггеры — для ночной копии).
5. Внизу, в «Журнале выполнения» — **логин и пароль методиста**. Запишите: пароль больше нигде не показывается.
6. **Развернуть → Новое развертывание** → ⚙ Тип: **Веб-приложение** → Выполнять как: **Я**, Доступ: **Все** →
   **Развернуть** → скопируйте ссылку `…/exec`.
   Проверка: ссылка в браузере отвечает `{"ok":true,"app":"buraq-lms","v":2,"ready":true}`.
7. **Адрес — в страницу.** На GitHub: `config.js` → ✎ → между кавычками в `window.LMS_SERVER = ''` вставьте
   ссылку `…/exec` → **Commit changes** (в основную ветку). Через 1–2 минуты сайт пересоберётся. Или пришлите ссылку
   Claude — он впишет.
8. **Первый вход методиста** на сайте: уровни, программы, план адаптации и график работы подставятся из шаблонов.
   «Kontent» → внизу слева **«Prototip faylidan 4-bobni yuklash»** → выберите исходный `.html` прототипа из Claude:
   тексты и тесты 4-bob уйдут на сервер. Вводный раздел прототипа «Kompaniya bilan tanishuv» — пример, а не правила
   компании: он не загружается, настоящий вводный раздел методист пишет сам («+ Bo‘lim qo‘shish»).
9. **Сотрудники:** «Xodimlar» → «Yangi xodim» → имя, должность, отдел, логин; пароль подставлен — передайте логин
   и пароль сотруднику. «Parolni tiklash» в строке сотрудника выдаёт новый.

Забыли пароль методиста — в редакторе функция **`newAdmin`** → ▶ Выполнить: новый вход методиста (`metodist2`, …)
в журнале выполнения.
**Обновление кода сервера:** у методиста внизу страницы «Server kodini nusxalash» (или `tools/lms-gs/Code.gs` на GitHub)
→ вставить вместо кода в Apps Script → Сохранить → **Развернуть → Управление развертываниями** → ✎ → Версия: **новая** →
Развернуть. Ссылка не меняется. Если код сервера старее страницы, методист видит предупреждение внизу слева.

### Видео уроков

Ролики — на YouTube того же аккаунта с доступом **«По ссылке»** (YouTube Studio → «Создать» → «Добавить видео» →
«Параметры доступа» → «По ссылке»). Ссылку — в урок: «Kontent» → урок → поле «YouTube havolasi» → «Saqlash».
Урок показывает ролик через `youtube-nocookie.com`; ссылка доходит до сотрудника только после входа, поверх урока — водяной
знак с его именем. Кто получил ссылку, может её переслать — если ролики станут секретнее, их можно перенести на платный
Vimeo с показом только на этом сайте, в уроке поменяется только ссылка. Без ссылки в уроке — заглушка плеера.

### Запросы

POST на `…/exec`, тело — JSON (`Content-Type: text/plain`, чтобы браузер не делал предварительный запрос),
ответ — `{ ok: true, … }` или `{ ok: false, code, error }`.

| action | Кто | Что делает |
| --- | --- | --- |
| `ping` | все | версия сервера, настроен ли |
| `login` `{login, password}` | все | `{token, me, rev}`; коды ошибок `login`, `locked` |
| `logout` | вошедший | закрывает вход на этом устройстве |
| `load` | вошедший | `{v, rev, me, state}` — состояние, которое ему положено видеть |
| `since` `{rev}` | вошедший | `{same: true}`, если ничего не менялось, иначе как `load` |
| `patch` `{ops}` | вошедший | правки (`lms-sync.js`), `{rev, applied, rejected: [{i, reason}]}`; `data:`-файлы — на Диск |
| `quiz` `{lessonId, answers}` | вошедший | балл теста и правильные ответы — после сдачи |
| `retest` `{errorId, answers}` | вошедший | повторная проверка после ошибки (3 первых вопроса урока) |
| `file` `{id}` | вошедший | файл `lmsfile:<id>`, если ссылка на него вам видна |
| `password` `{old, password}` | вошедший | смена своего пароля (от 8 символов), другие устройства выходят |
| `resetPassword` `{userId}` | методист | новый пароль сотруднику — показывается один раз |

Другие коды ошибок: `auth` — нужен вход, `forbidden` — нет прав, `busy` — сервер занят записью (повторить),
`setup` — не запущен `setup`, `bad` — неверный запрос.

## Как страница работает с сервером

- `update(fn)` меняет данные, как в прототипе; `lms-client.js` считает разницу «было → стало» и кладёт её в очередь
  на устройстве, через полсекунды — на сервер пачкой. Пока правка не дошла, она видна на экране.
- Без сети правки ждут на устройстве (внизу слева — «Internet yo‘q…»), уходят сами при появлении сети.
- Раз в 30 секунд, при возврате на вкладку и при появлении сети — «что нового» (`since`).
- Номера новых записей — время и случайная часть (у двух устройств `seq + 1` совпал бы).
- Тест урока и повторная проверка — на сервере: у сотрудника правильных ответов нет, их показывают после сдачи.
- Месячный отчёт выпускает только методист. Журнал нарушений защиты урока обрезает сервер (последние 500).
- Язык и вход — только на устройстве.

## Локальный запуск

```bash
node tests/lms-dev-server.mjs        # http://localhost:8790/ — сервер на заглушке, логин и пароль методиста в консоли
node tests/lms-e2e.mjs [папка]       # проверка в браузере от входа до итога экзамена (нужен Playwright)
python3 -m http.server 8000          # http://localhost:8000/ — демо, без сервера
```

## Известные ограничения

- XP за опросы и ИИ-тренировки считает страница — при желании их можно накрутить через инструменты разработчика.
  Итог урока решает устный экзамен у методиста, его сотрудник не поставит.
- Все данные (кроме файлов) — один файл: каждая запись переписывает его целиком. Для десятков и сотен сотрудников этого
  хватает. Если станет медленно, файл можно разделить (курс, люди, журналы).
- Apps Script отвечает за 1–2 секунды; вход — чуть дольше (хэш пароля).
- Заменённые файлы (новый скан паспорта) остаются в папке `files` — их можно удалить вручную.
- Страница работы без сети не кэширует свои файлы: открыть её без интернета можно, только если браузер держит её в кэше.
  Данные и правки без сети работают.
